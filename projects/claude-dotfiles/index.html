문제와 시작

AX 프로젝트를 빠르게 구현해도 품질·리뷰·배포 안전장치·반복 실수 방지·맥락 기억이 남지 않으면 현업 적용 속도가 유지되지 않습니다. 요즘 유튜브에 도는 에이전트 하네스·루프 엔지니어링·RAG 기억은 데모로는 흔하지만, 실제 납품 현장에서 굴러가는 형태로 만드는 건 다른 문제였습니다.

직접 한 일

세 층으로 만들었습니다. ① 규칙 — Claude Code·Codex가 같은 공통 지침을 읽고, 훅이 작업 트리 직접 수정·검사 우회·확인 범위 없는 단정을 막습니다. ② 검증 — 완료를 자기보고가 아니라 독립 재검증으로 확인합니다. 2026년 6월 완료 게이트(kdh)로 시작해, 지금은 독립 리뷰를 다른 모델(Codex)에 맡기고 검사는 중앙 등록부에서 CircleCI와 서버 대기열로 돌리며, Jules가 시험 없는 파일의 시험을 써서 통과분만 병합합니다. ③ 기억 — Claude·Codex가 같은 공유 기억과 PDF 문서 검색을 씁니다. 다만 트렌드를 그대로 따르지 않고, 무엇을 들이고 무엇을 안 들일지는 har_eval로 측정해 갈랐습니다.

결과와 현재 상태

개인 생산성 도구를, AX 프로젝트를 계속 납품할 수 있는 재사용 가능한 운영 하네스 — 검증 루프·자율 루프·장기 기억까지 — 로 바꿨습니다. 트렌드를 좇은 게 아니라 측정으로 만들 것과 안 만들 것을 갈랐습니다. 지금은 배포 등록부 27개 제품의 빌드·배포·검사·백업을 이 저장소가 맡고, 2026년 11월부터 Rust 제품의 검사도 같은 경로로 돕니다. 개발 도구 · 화면이 없는 설정 저장소라 실제 명령 실행 결과를 터미널 화면으로 옮겼습니다.
