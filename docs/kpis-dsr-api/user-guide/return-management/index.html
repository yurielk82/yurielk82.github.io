반송 줄 고쳐 다시 보고하기

KPIS가 반송한 줄을 사유에 맞게 고쳐 다시 보고합니다. 보고 기한이 지난 줄은 반송신청으로 고칩니다.

시작 전에 필요한 것

  • 줄을 고치는 계정. 다시 보고와 반송신청은 관리자만 합니다.
  • 반송 사유 코드. 반송 줄마다 KPIS가 준 코드와 해결 방법이 함께 보입니다.

반송 줄 찾기

  1. 대시보드의 반송·반송신청 줄에서 반송 처리를 누릅니다. 사이드바 KPIS 보고를 열고 반송 처리 탭을 눌러도 됩니다.
  2. 그 달 반송 줄이 날짜별로 보입니다. 줄마다 공급구분, 사유, 해결 방법 분류가 붙습니다.
분류뜻
데이터 수정틀린 칸을 고쳐 다시 보냅니다
단가단가 오류(DC·DE·DH)입니다. 거래명세서 단가와 같으면 다시 보낼 때 반송사유코드가 자동으로 적힙니다
확인 필요사람이 원인을 판단해야 합니다
결과 미확인반송이 아니라 결과를 모르는 줄입니다. KPIS에 보고하기의 결과 미확인 정리를 따릅니다

반송 줄 고쳐 다시 보고하기

  1. 반송 처리 탭에서 고칠 날짜 옆의 그리드에서 고치기를 누릅니다. 반송 관리 화면에 그날 반송 줄만 걸러 열립니다.
  2. 해결 방법에 적힌 칸을 고칩니다. 칸에서 벗어나면 그 줄이 저장됩니다.
  3. 단가 오류처럼 반송사유코드만 적으면 되는 줄이 몇 개인지 보려면 위쪽 오류 자동해결을 누릅니다. 줄 수를 알려 줄 뿐 보고 상태를 바꾸지는 않습니다.
  4. 고친 내용을 보려면 수정이력을 누릅니다.
  5. 바로 보내려면 관리자가 저장하고 반송 줄 다시 보고를 누릅니다. 보고 계획이 열립니다.
  6. 계획을 확인하고 API 보고 시작을 누릅니다.

바로 보내지 않아도 됩니다. 자동 보고가 켜져 있으면 고친 지 20분이 지난 줄을 다음 자동 보고(물류 마감 적재 직후 또는 밤 11시)가 보냅니다.

결과 확인

  • 반송 처리 탭에서 그 줄이 사라지면 접수된 것입니다.
  • 날짜 카드가 보고 완료 · API 접수 확인으로 바뀝니다.
  • 다시 반송되면 그 줄은 사람이 다시 고칠 때까지 자동으로 보내지 않고 로그에 남습니다.

다시 보내는 줄의 범위

저장하고 반송 줄 다시 보고는 아래 줄만 보냅니다.

  • 반송된 뒤 내용을 고친 줄(을지 일련번호 포함)
  • KPIS에 내용이 닿지 않은 줄(보내기 전 사전점검에서 막힌 줄, 결과 미확인을 미접수로 돌린 줄)

KPIS가 같은 내용으로 반송했고 아직 고치지 않은 줄은 뺍니다. 고친 줄이 없으면 버튼을 눌렀을 때 그 줄 수를 알려 줍니다. 반송 줄이 있어도 그날 다른 줄 보고는 막지 않습니다.

자주 나오는 반송 코드

코드이름고치는 법
FE표준코드 포장 내 총수량 오류공급규격(포장내총수량)을 표준코드 마스터에 맞춥니다
FA표준코드 오류표준코드를 고칩니다. 바코드 서버 마스터가 틀렸으면 표준코드 정정 제안을 봅니다
DA공급단가·수량·금액계산 오류공급금액이 공급수량×공급단가와 맞는지 봅니다
DC, DE, DH급여 전문·비급여·급여 일반의약품 단가 오류거래명세서 단가와 같으면 반송사유코드를 적어 다시 보냅니다
CN거래처 미등록·불일치 오류업무포털 공급업체정보관리에 거래처를 등록하거나 정보를 맞춥니다
KJ사업자번호·요양기관기호 오류요양기관정보조회로 확인한 사업자번호·요양기관기호로 보고합니다
JD정정·취소 기간초과 오류기한이 지났으므로 아래 반송신청으로 고칩니다

코드 뜻은 심평원 「OpenAPI 개발가이드」 반송사유코드를 따릅니다. 화면의 반송 줄마다 해당 코드의 해결 방법이 함께 보입니다.

기한이 지난 줄 고치기(반송신청)

정정·취소는 공급월 다음 달 말일까지 출고 줄에만 할 수 있습니다. 그 뒤이거나 반품·폐기 줄이면 반송신청을 합니다.

  1. 대시보드 › 할 일에서 그날 카드의 ⋯ 메뉴를 열고 변경 내용 확인을 누릅니다.
  2. 고칠 줄 옆에서 반송 사유를 고르고 **운영 서버로 신청(되돌릴 수 없음)**에 표시합니다.
  3. 반송신청을 누릅니다.
  4. 심평원은 하루 세 번(09:30, 13:30, 17:30) 승인합니다. 서버가 그 10분 뒤 결과를 받아 옵니다. 바로 보려면 반송 처리 탭의 반송신청 목록에서 결과 다시 보기를 누릅니다.
  5. 승인되면 업무포털 반송현황에서 반송보고로 고친 값을 보고합니다. 그 줄을 지우려면 보고안함을 누릅니다. 이 단계는 API가 없어 포털에서만 합니다.

주의: 기한이 지난 줄을 원 줄을 지우고 새 줄로 다시 보내면 KPIS가 늦은 보고로 세어 적기보고율이 떨어집니다. 반송신청 뒤 반송보고로 고친 줄은 적기보고율 계산에 들어가지 않습니다.

반송신청에 응답이 없어 결과를 모르는 신청은 같은 줄로 다시 신청할 수 없습니다. 업무포털 반송현황에 그 신청이 없음을 확인한 뒤 신청 없음 확인 — 닫기를 누르면 다시 신청할 수 있습니다.

잘 안 될 때

  • 저장하고 반송 줄 다시 보고를 눌렀는데 고친 줄이 없다고 나오면, 틀린 칸을 실제로 고쳤는지 수정이력에서 확인합니다.
  • 반송 줄을 고칠 수 없으면 그 줄이 접수·결과 미확인 상태인지 봅니다. 화면에서는 미보고 줄과 반송 줄만 고칠 수 있습니다.
  • 그 밖은 문제 해결을 봅니다.
