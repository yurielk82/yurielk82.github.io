웹 화면 구성

이 쪽은 web/ 폴더의 Next.js 웹 화면 구조와 로그인 흐름, 데이터를 가져오는 길을 정리한 참고 자료입니다.

기술

항목내용
프레임워크Next.js 16(App Router), TypeScript
UIMantine
서버 상태TanStack Query
화면 상태Zustand
코드 보기Monaco Editor
패키지 관리pnpm

경로

경로화면로그인
/loginGoogle 로그인필요 없음
/pending-approval승인 대기로그인만
/대시보드승인 필요
/simulation시뮬레이션승인 필요
/monitor모니터(화면 제목 “실시간 모니터”)승인 필요
/sample-data실측 데이터(화면 제목 “실측 데이터 관리”)승인 필요
/analysis분석승인 필요
/code코드승인 필요
/admin관리관리자
/avl-converterAVL XML Profile Converter필요 없음

승인이 필요한 화면은 web/app/(protected)/ 아래에 있고, 공통 레이아웃이 매 요청마다 사용자 상태를 확인합니다.

로그인 흐름

  1. 사용자가 /login에서 Google로 로그인합니다. Neon Auth가 세션을 만듭니다.
  2. 보호된 화면 레이아웃이 사용자 역할과 차단 사유로 상태를 정합니다.
  3. 처음 로그인한 사용자는 승인 대기로 바뀌고 /pending-approval로 갑니다.
  4. 거절된 사용자는 /login?error=rejected로 가서 접근 거절 안내를 봅니다.
  5. 관리자는 사용자 메뉴의 사용자 관리에서 승인 대기, 활성 사용자, 거절 / 차단 목록을 보고 승인이나 거절을 누릅니다.

web/middleware.ts는 /avl-converter와 /api/v1/avl-converter를 로그인 검사에서 뺍니다.

데이터를 가져오는 길

웹 화면은 데이터를 세 길로 가져옵니다.

길쓰는 곳
브라우저 → /agent-api → API /api/v1시뮬레이션, 모니터, 분석, 실측 데이터, 코드, 채팅, 연결 상태
웹 서버의 API 경로 → Neon PostgreSQL대시보드 지표(/api/metrics), 최근 시뮬레이션(/api/history), 실측 데이터 요약(/api/sample-data/summary)
웹 서버의 API 경로 → 스크립트 생성API가 없을 때 다운로드로 받는 Python 스크립트(/api/script)

/agent-api 경로는 web/next.config.ts의 rewrite가 AGENT_BACKEND_URL로 넘깁니다. 운영에서는 같은 서버의 API를 가리킵니다.

폴더

폴더내용
web/app/경로별 화면과 웹 서버 API 경로
web/components/레이아웃, 대시보드, 시뮬레이션, 분석, 코드, 채팅, 인증 화면 조각
web/hooks/연결 상태, API 호출 훅
web/stores/에이전트, 시뮬레이션, 테마, 채팅 상태
web/lib/API 클라이언트, 시뮬레이션 기본값, DB, 인증
web/types/연결 상태, 인증, 코드 화면 타입

빌드

cd web
pnpm install
pnpm run build

운영 배포는 standalone 결과물을 씁니다. 순서는 구성과 배포에 있습니다.
